# الملف المفقود

> الملف كان هنا قبل قليل… فمن أخفاه؟

لعبة اجتماعية جماعية متعددة الأجهزة لقوسي — التأمينات الاجتماعية السعودية.
من 4 إلى 8 لاعبين، جهاز رئيسي يقود الجلسة بالصوت، وجهاز شخصي لكل لاعب،
وملف مطبوع بطابعة 3D في منتصف الطاولة يختفي أثناء الليل.

**الاسم مؤقت** وقابل للتغيير من ملف واحد: [`src/config/game.config.ts`](src/config/game.config.ts).

---

## التشغيل

```bash
npm install
npm run dev
```

افتح `http://localhost:5173`:

- **جهاز المضيف:** اضغط «إنشاء جلسة» → يظهر رمز وQR ورابط.
- **أجهزة اللاعبين:** افتح الرابط أو امسح الـ QR على كل جهاز.

## ⚠ اللعب بين الأجهزة يحتاج Firebase

بلا متغيرات `VITE_FIREBASE_*` يعمل المشروع على **النقل المحلي**: الجلسة تُحفَظ في
تخزين المتصفح نفسه. عدة تبويبات في متصفح واحد تُشكّل جلسة كاملة للتجربة، لكن
**لا يستطيع أي جهاز آخر الانضمام** — لا بالرمز ولا بالرابط ولا بمسح QR، لأنه لا
يوجد خادم مشترك تُقرأ منه الجلسة. التطبيق يقول ذلك صراحةً في الشاشة الرئيسية
وفي ردهة المضيف بدل أن يعطي رمزًا لا ينفع.

للتشغيل الحقيقي:

1. أنشئ مشروعًا في [console.firebase.google.com](https://console.firebase.google.com)
   وفعّل **Realtime Database**.
2. انسخ قواعد الأمان من [`firebase/database.rules.json`](firebase/database.rules.json)
   إلى تبويب Rules.
3. من إعدادات المشروع خذ قيم إعداد الويب، وضعها في `.env` محليًا أو في متغيرات
   بيئة النشر (Vercel: Settings → Environment Variables):

```bash
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=<project>.firebaseapp.com
VITE_FIREBASE_DATABASE_URL=https://<project>-default-rtdb.firebaseio.com
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_APP_ID=...
```

4. فعّل **Anonymous** في Authentication → Sign-in method.
5. أعد النشر. المتغيرات تُدمج وقت البناء، فلا يكفي إضافتها بلا إعادة نشر.

للتحقق: الشاشة الرئيسية تُظهر شارة «متصل بـ Firebase» بدل إشعار «بلا خادم».
التفاصيل ومسار الترقية إلى Cloud Functions في
[`docs/FIREBASE_SCHEMA.md`](docs/FIREBASE_SCHEMA.md).

| الأمر | الغرض |
|---|---|
| `npm run dev` | خادم التطوير |
| `npm test` | 97 اختبارًا للقواعد والمنطق وطبقة النقل (بلا شبكة) |
| `npm run test:live` | يشغّل `FirebaseTransport` الحقيقي على قاعدة البيانات المنشورة |
| `npm run verify:rules` | يدقّق القواعد الأمنية بثلاث هويات مجهولة منفصلة |
| `npm run typecheck` | فحص الأنواع |
| `npm run build` | بناء الإنتاج |

مسارات مفيدة: `#/roster` — ورقة الشخصيات (10 شخصيات × 9 حالات) للمراجعة البصرية.

## بنية المشروع

```
src/
├── config/game.config.ts   ← الاسم والمصطلحات والافتراضيات — نقطة تغيير واحدة
├── game/                   ← منطق نقي، بلا شبكة وبلا React
│   ├── rules.ts            ← جدول القواعد حسب عدد اللاعبين
│   ├── seating.ts          ← المقاعد والجيران يمينًا ويسارًا
│   ├── deal.ts             ← توزيع الأدوار والنرد
│   ├── night.ts            ← الاستيقاظ المنفرد وفحص الجار
│   ├── accomplice.ts       ← قواعد المتعاونين 5–8
│   ├── vote.ts             ← التصويت وشروط الفوز
│   ├── director.ts         ← تنسيق المضيف (مرشّح للنقل إلى Cloud Functions)
│   └── roster.ts           ← الشخصيات كمعطيات
├── net/                    ← طبقة النقل خلف واجهة واحدة
│   ├── transport.ts        ← العقد
│   ├── firebaseTransport.ts← الإنتاج (تحميل ديناميكي)
│   └── localTransport.ts   ← التطوير والاختبار بلا خادم
├── audio/                  ← النص الصوتي العربي + مدير الصوت
├── ui/                     ← Design Tokens + مكوّنات الفن + العناصر
└── screens/host|player/    ← الشاشات

scripts/                    ← خط إنتاج الفن
├── art-spec.mjs            ← كل موجّهات GPT Image — مصدر واحد للأسلوب
├── slice-sheet.mjs         ← تقطيع ورقة النماذج 3×3 إلى تسع حالات
├── process-art.mjs         ← إزالة الخلفية + أكبر شكل متصل + قص وتصدير
└── fetch-art.mjs           ← جلب الأصول المولّدة إلى public/

public/                     ← الأصول النهائية: characters, props, scenes
```

**قاعدة معمارية:** الشاشات لا تعرف Firebase، والمنطق لا يعرف React.
كل قرار يحسم اللعبة دالة نقية قابلة للاختبار.

## الحالة الحالية

**متصل بقاعدة بيانات حقيقية** — مشروع `who-hid-the-file` على Firebase،
القواعد منشورة، والدخول المجهول مفعّل. `npm run verify:rules` يثبت العزل
بهويات منفصلة، و`npm run test:live` يشغّل النقل الحقيقي على القاعدة نفسها.

**جاهز ومختبَر:**
إنشاء الجلسة والانضمام · ترتيب الجلوس بالسحب · توزيع الأدوار · النرد الرقمي والحقيقي ·
وضع الأربعة لاعبين · مراحل الليل الست بالصوت والعد التنازلي · الاستيقاظ المنفرد ·
فحص الجار · المتعاونون 5–8 · التصويت المتزامن السري · الكشف والنتائج · جولة جديدة ·
الإيقاف والاستئناف.

**الفن:** 102 أصلًا مولّدة عبر GPT Image — 10 شخصيات × 9 حالات، الملف ومكانه
الفارغ، 6 وجوه نرد، و4 مشاهد مجلس. خط الإنتاج كامل في `scripts/` وقابل لإعادة
التشغيل من ملف موجّهات واحد. راجعها على `#/roster`.

**يحتاج عملًا قبل الإنتاج:**

1. **نقل `director.ts` إلى Cloud Functions** — المضيف اليوم طرف موثوق يقرأ الأسرار.
   العزل بين اللاعبين كامل، لكن ثقة المضيف تحتاج خطة Blaze لإزالتها.
   راجع [`docs/FIREBASE_SCHEMA.md`](docs/FIREBASE_SCHEMA.md).
2. **خط عرض عربي مستضاف ذاتيًا** — الحالي مكدّس خطوط النظام فيختلف بين الأجهزة.
3. **تسجيلات صوتية بشرية** — TTS حل مؤقت وجودته تختلف؛ كل الجمل مكتوبة وجاهزة.
4. **ملفات الطباعة 3D** — المواصفات محدّدة والمساحة مجهّزة.
5. **تنظيف الغرف القديمة** — Scheduled Function تمسح ما مضى عليه 24 ساعة.
6. **حذف الغرفة من الواجهة** — لا يوجد `closeRoom` في `RoomTransport`؛
   الاختبار الحيّ ينظّف بإزالة الفروع مباشرة.
7. **تمريرة رسّام على الأصول** — المولَّد صالح للإنتاج، لكن تمريرة بشرية
   ستضبط الاتساق الدقيق بين حالات الشخصية الواحدة.

## الأصالة

اللعبة مستوحاة من **البنية العامة** للعب الاجتماعي في *Cheese Thief*:
دور سري، مواعيد استيقاظ مختلفة بالنرد، عنصر فيزيائي يختفي من الوسط، معلومات جزئية،
نقاش وتصويت.

**لم يُنسخ** أي نص أو رسم أو بطاقة أو اسم أو علامة تجارية.
القصة والشخصيات والرسومات والنصوص الصوتية والواجهة كلها أصلية.
جدول الفروق الكامل في [`GAME_RULES.md §12`](GAME_RULES.md).

**لم يُخترع شعار لقوسي.** اسم الجهة يُعرض كنص فقط، وكل الألوان في Design Tokens
مركزية للاستبدال فور توفّر الهوية الرسمية.
